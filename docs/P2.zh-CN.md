# P2 — L1 数据流实验组合

对应英文版：[`P2.md`](P2.md)

修订：2026-08-22

公开指南：[运行 L1 节点](https://gitbook.conet.network/developers/l1-node.html) ·
[Linux 运行时](https://gitbook.conet.network/developers/conet-l0d.html)

## 1. 状态与边界

P2 记录一项实验组合：通过应用所使用的同一套持续 `web3://`
传输，承载选定的 geth 或 Prysm TCP 数据流。

这是实验室工作，不是公开 L1 加入合同。公开运营者仍通过文档中的
geth 与 Prysm P2P 路径加入 CoNET L1。P2 不代表现有 validator、
beacon 节点或执行客户端已经迁移到 Layer Minus。

## 2. 复用应用传输

该组合复用 P1 数据流合同：

```text
本地 L1 进程
    ⇅ TCP
conet-l0d 客户端 endpoint
    ⇅ 加密 Layer Minus session
conet-l0d --proxyDuplex
    ⇅ TCP
远端 L1 进程
```

应用身份仍是钱包地址或精确 BeamioTag：

```text
web3://<wallet-or-tag>:8400
web3://<wallet-or-tag>:4200
```

端口属于应用元数据：

| 端口 | 实验用途 |
|---:|---|
| `8400` | geth devp2p TCP 数据流 |
| `4200` | Prysm libp2p TCP 数据流 |

该实验不新增 SI 命令族或公开 endpoint，而是使用现有 Layer Minus
entry/mailbox attachment 路径与版本化应用 session 消息。

## 3. 实验记录

2026 年 8 月的双主机实验使用：

| 角色 | 公网主机 | Overlay endpoint |
|---|---|---|
| Spoke | `74.208.224.45` | `100.64.0.5` |
| Hub | `198.251.77.98` | `100.64.0.6` |

Hub 用 `--proxyDuplex` 发布本地 L1 服务。Spoke 通过 `web3://`
目标选择 Hub，并提供本地客户端 endpoint。现有 geth 与 beacon
进程随后通过普通 TCP 使用这些本地 endpoint。

该实验验证了：

1. 钱包地址化双向 offer 被接受；
2. 双向加密 frame 持续传输；
3. 选定 L1 服务的 TCP 连接保持稳定；
4. 应用数据流中断后可以重连；
5. geth 与 Prysm peer identity 保持不变。

上表地址是实验室事实，不是通用默认值。

## 4. 验收证据

只有在所有适用证据一致时，才能认为 P2 正在运行：

| 层 | 证据 |
|---|---|
| Runtime | `conet-l0d status` 报告预期 server 与 client endpoint |
| Layer Minus | 日志显示 duplex session 已接受，且加密 frame 持续出现 |
| TCP | 选定的本地与远端服务连接保持 established |
| Geth | `net_peerCount` 与预期 enode 确认执行层 peer |
| Prysm | `/eth/v1/node/peer_count` 与 peer identity 确认共识层 peer |
| Sync | head slot 上升，sync distance 随时间下降 |

daemon 正在运行本身，不能证明 L1 peer 已连接。

## 5. 重连与恢复

恢复应从应用传输向外排查：

1. 确认本地服务和已发布 upstream 正在监听；
2. 确认钱包路由和 duplex session；
3. 确认双向加密 frame 持续传输；
4. 确认 L1 客户端存在 established TCP peer；
5. 最后才诊断 geth 或 Prysm peer 状态。

重启 geth、beacon-chain 或 validator 始终是运营者的明确决定，并且需要
事先授权。传输诊断不得静默重启链基础设施。

## 6. 范围外

P2 不会：

- 替代公开 geth/Prysm 节点加入指南；
- 定义通用 IP 网络；
- 让浏览器客户端运行 L1 共识软件；
- 新增公开域名或 SI wire 命令；
- 承诺 L1-over-L0 已达到生产可用；
- 把 SilentPass 变成 L1 共识传输。

早期 datagram 与 discovery 实验只作为工程历史保留，不属于公开
`web3://` 应用合同。

## 7. 与产品的关系

产品层次为：

1. **Layer Minus（L0）**提供加密、钱包路由的传输。
2. **`web3://`**定义应用 locator 与 session 合同。
3. **`conet-l0d`**提供 Linux server/client 运行时。
4. **P2**探索该运行时承载选定 L1 TCP 数据流的一种可选
   Linux-to-Linux 用法。

无论 P2 实验状态如何，该应用协议仍可服务普通应用以及浏览器或原生客户端。
