# P2 — 在现有 overlay 信封上做实验室 UDP / discv5 通讯实验

**成对译本：** [English](./P2.md)  
**Revision:** 2026-08-18（overlay UDP 已验收；L0_ONLY `.45` 经 L0 连 `.98` DHT 服务器的现役 Prysm discv5 已验收；掉线先清幽灵 conntrack；拨号 backoff 后授权 `.45` `restart-beacon` 可恢复 overlay libp2p TCP；`ss` 上的公网 `:4200` 是 DNAT 原目的、不是漏公网；不是生产 discv5 产品）

公开 how-to：[Applications](https://gitbook.conet.network/applications/conet-l0d.html) · [Developers](https://gitbook.conet.network/developers/conet-l0d.html)

本页是 **实验室通讯实验**。它 **不** 关闭 [P1](./P1.zh-CN.md) 追链门。它 **不是** 生产 discv5 / 混合 P2P 产品。

## 目标

证明 Layer Minus overlay（crate 信封 + TUN）能运 **操作系统 UDP**，包括 beacon DHT 口 `:4300`；并且 L0_ONLY beacon 可以 **放弃公网 / 静态 `--peer`**，仍经 L0 与公网 DHT 服务器通讯。不新增 SI 命令，也不走现役 `udp_subscribe` / `udp_relay`。

## 为什么不是新的 datagram 适配器

overlay 信封已经是完整 IPv4 数据报（或多个按 `tot_len` 拼接）。协议 17 已在范围内。现役 SI UDP 转发是 HTTP/SSE 上的 AES 帧，**不是** 这条路径。

## 实验室对象（操作员脚本，不是 `CONET_L0D`）

| 脚本 | 主机 | 作用 |
| --- | --- | --- |
| `scripts/probe-l0-udp.sh` | 两机 | 回声 / 发 `:4300` / 公网 ENR steer / TUN 抓包 |
| `scripts/overlay-beacon-listen-dnat.sh` | 通告公网的对端（`.98`）与 L0_ONLY `.45` | overlay VIP 的 tcp/udp DNAT/SNAT 进公网 listen（除 geth `:8400`）。TUN 上设 `accept_local` / `route_localnet` / `rp_filter=0`，才能把 DNAT 到本机公网 listen 的 SYN 真正交给 socket。UDP SNAT 保持 overlay VIP（不要 SNAT 成公网 IP）。`apply` 只 flush overlay **beacon** `:4200/:4300` conntrack — 不动公网枢纽 peer，也不动 geth `:8400`。 |
| `scripts/overlay-dht-steer.sh` | L0_ONLY `.45` | 把枢纽 `:4300`/`:4200` DNAT 到 `100.64.0.6`；MARK 在 DNAT **之后**（mangle POSTROUTING，目的 VIP）；表 6300 含 overlay CIDR **以及** 枢纽公网 `/32` 走 TUN；`apply` 会清掉枢纽 `:4300`/`:4200` 的旧 conntrack（**重连第一步**；不重启 geth/beacon） |
| `scripts/start-shared-beacon-98.sh restart-beacon` | `.98` | `--p2p-static-id` DHT 枢纽。**不**重启 geth |
| `scripts/start-geth-beacon-only.sh enable-l0-dht` | `.45` | 写 `L0_ONLY=1` + `L0_DHT=1`（及 bootstrap ENR）。**不**重启 EL/CL |
| `scripts/start-geth-beacon-only.sh restart-beacon` | `.45` | 套用 `L0_DHT`：去掉 `--no-discovery`。默认有 `L0_DHT_BOOTSTRAP_ENR` 时也去掉静态 `--peer`。`L0_DHT_NO_STATIC_PEER=0` 保留 overlay `--peer`。缺 `CONET_L0D_DHT_STEER` 对枢纽 `:4300`/`:4200` 的 DNAT 则 fail-closed |

**不要**改守护进程自有的 `CONET_L0D`。隔离链仍是 `CONET_L0D_P2P_ISOLATE` / `_OUT`。

垃圾 UDP 探针不会得到 discv5 回包。对端 TUN 上看到到达即通讯证明。随后的现役 bounce 用同一条路径跑真 discv5 + libp2p。

## 现役 bounce 怎么做

经授权的 **只重启 beacon**（不 wipe、不起 validator、两机 **都不动 geth**）：

```bash
# .98 — 固定 peer id，继续通告公网
./start-shared-beacon-98.sh restart-beacon
# 再套 overlay-beacon-listen-dnat.sh
# 从本机 identity 抄 ENR

# .45 — 放弃静态 --peer；discv5 走 bootstrap ENR + steer
L0_DHT=1 L0_DHT_BOOTSTRAP_ENR='enr:…' ./start-geth-beacon-only.sh enable-l0-dht
./overlay-dht-steer.sh
./start-geth-beacon-only.sh restart-beacon
```

`.98` 仍通告 `198.251.77.98` 并保留公网对等。`.45` 通告 overlay `100.64.0.5`，不得拉公网 `:4110` ENR。`L0_DHT` 先 `--p2p-allowlist=100.64.0.0/10`，再 `--p2p-allowlist=198.251.77.98/32`（Prysm v7.1.4：每条 flag 一个 CIDR，后写覆盖）。最后这条 `/32` 才让 Prysm 对 bootstrap ENR 做 `connect()`；报文仍走 L0，因为 `overlay-dht-steer.sh` 把枢纽 `:4300`/`:4200` DNAT 到 `100.64.0.6`。有 bootstrap ENR 时丢掉 overlay `--peer`（只走 discv5）。`L0_DHT_NO_STATIC_PEER=0` 是 P1 恢复开关，不是已验收的 DHT 主路径。缺 steer 时启动 **fail-closed**（否则隔离链会丢掉真公网拨号）。**不要**把它写成 `FOLLOW_OK` 或 P2 产品完成。EL 可以仍停在 `0x0`。

## `--peer` 与 discv5

| | 静态 `--peer` | DHT / discv5（`--bootstrap-node=<ENR>`） |
| --- | --- | --- |
| 事先必须知道 | 该对等的 multiaddr（IP + TCP + **peer id**） | 至少一份 **引导 ENR**（node id **以及** IP + UDP 都在 ENR 里） |
| 拨号 | 直接 libp2p `connect()`；发现可选 | 先 UDP discv5，再 libp2p TCP |
| 从未写入命令行的节点 | 不会找到 | 入网 **之后** 可查 |
| 实验室 `.45` 配了 `L0_DHT_BOOTSTRAP_ENR` | 已去掉（验收路径） | 必须。isolate + allowlist last-wins `/32` 使 `.45` **不能**从公网 `:4110` ENR 发现 `.98` |

连 **这一台 DHT 枢纽** 仍要它的 ENR。「不必事先知道 DHT 的 ID」只对入网后遇到的 **其他** 节点成立，对引导节点不成立。

`.98` 的 `--p2p-static-id` 让该 ENR 在 beacon 重启后仍有效。`.45` REST `last_seen` 可能写成 `/ip4/198.251.77.98/tcp/4200`（ENR + conntrack 原目的），而 TUN 上是 `100.64.0.5` ↔ `100.64.0.6:4200`，`.98` 上 `ss` 是来自 `100.64.0.5:4200` 的入站（线上走 TUN）。**不要**把 `.45` `ss` 里的公网目的当成「隔离失败」。

## 枢纽 IP 与钱包身份

未改的 Prysm discv5 **不会**只凭钱包或 peer id 拨号。枢纽 ENR 必须带可拨 IP。实验室 `.98` 仍通告公网 `198.251.77.98` 并保留公网对等 — 这是公开 discv5 枢纽，不是匿名节点。

L0 藏的是 **客户端** 对对端的公网 IP（isolate + steer）。双方都匿名（发现记录无 IP、SI 入口看不见源 IP、链上无 route）**不是**本实验室，也 **不是** 库存 discv5。

## 掉线：先清幽灵 conntrack，不重启 EL/CL

steer / listen-DNAT 是 **操作员** 对象，不属于 `CONET_L0D`。`conet-l0d stop` 会拆 TUN；下次 `start` 后必须重打 steer。负载 watchdog 只按 load15 启停 **geth**，不管 DHT。

**2026-08-18 约 11:14Z：** `.45` beacon `connected` 1→0；`head_slot` 冻在 `778719`。overlay **geth** 仍 ESTAB（`100.64.0.5` → `100.64.0.6:8400`），因为 geth 拨 overlay VIP，不拨公网 ENR。beacon conntrack 上枢纽 UDP `:4300` 为 **`UNREPLIED`**（已 DNAT 进 overlay，回包对不上）。isolate 丢掉发往 **其它** 公网 `:4300` 的包是 L0_ONLY 预期。`.98` 把 `.45` 标成 `disconnected inbound`，不会主动回拨（已有约 14 个公网 peer）。

**第一步恢复（做这个；不要重启 geth 或 beacon）：**

```bash
# 只在 .45 — 重装 DNAT/MARK 并 flush 枢纽 :4200/:4300 conntrack
cd /home/peter/conet-l0d-lab
./overlay-dht-steer.sh apply
```

**2026-08-18 11:49Z：** 该 `apply` 清掉了幽灵 UDP 映射；geth pid `884029` 与 beacon pid `890053` **未变**。约 60 秒后 `connected` 仍为 `0`（对枢纽 ENR `disconnected outbound`）。又出现 **新的** `UNREPLIED` UDP 探针 — discv5 在发，但 Prysm 停在 **进程内拨号 backoff**，没有开 TCP。Flush 足以修 NAT，**一旦进入 backoff 就不够**。

**仅当 flush 后 `connected` 仍为 0**（须授权只重启 `.45` beacon，不动 geth）：

```bash
./start-geth-beacon-only.sh restart-beacon
# steer 必须在启动 *之前* 打好。不要在 start 后立刻 overlay-dht-steer.sh apply
# —— 会 flush 掉 SYN_SENT，再次进入 backoff。
```

不要把 `P1 overlay batch flushed for POST` 当成 HTTP 2xx。不要加公网 `--peer` 或放开 isolate 来「修」DHT。

**2026-08-18 约 17:00Z `.98` listen-DNAT（未重启 `.98` EL/CL）：** discv5 UDP 仍进 `.98` TUN，beacon 有回包。TCP 只听 **`198.251.77.98:4200`**，overlay `100.64.0.6:4200` 必须 DNAT 进该 socket。这条 DNAT 需要 TUN `accept_local=1` / `route_localnet=1` / `rp_filter=0`，否则 NAT 计数了 SYN、socket 收不到（TUN 上无 SYN-ACK）。两机重打 `overlay-beacon-listen-dnat.sh`。**不要**在 apply 时 flush overlay geth `:8400` conntrack（早期 `apply` 把 `.45` `net_peerCount` 清成 `0x0`；geth pid 未变）。UDP SNAT 必须保持 overlay VIP。该 apply 后 `.98` 公网 `connected=14` 不变；`.45` beacon `connected` 仍为 `0`（backoff + UDP 仍 `UNREPLIED`）。**未**重启 `.98` 的 geth/beacon。

**2026-08-18 约 17:28Z 授权 `.45` `restart-beacon`（不动 geth）：** steer 已事先打好。启动后 **没有**再跑 `overlay-dht-steer.sh apply`。geth pid `900292` 仍 ESTAB 到 `100.64.0.6:8400`。beacon pid `899131` → `900670`。约 18 秒内 `connected=1`。TUN tcpdump：双向 PSH/ACK `100.64.0.5:4200` ↔ `100.64.0.6:4200`。`.45` `ss` 显示 `74.208.224.45:4200 → 198.251.77.98:4200`（DNAT 原目的）。隔离链 `tcp dpt:4200` DROP = 0。枢纽：`198.251.77.98:4200 ← 100.64.0.5:4200`。日志约 1 分钟仍写 `suitable=0`，随后 `Processing blocks`。`head_slot` 离开 `778656` 并上涨（约 3–6 slot/s；overlay RTT 约 0.7s；单 peer）。geth `eth_blockNumber` 仍为 `0x0` — 是 CL 追链滞后，不是 overlay 又断。**不要**把 EL `0x0` 或第一分钟的 `suitable=0` 当成重启失败。overlay `:8400` 仍 ESTAB 时 **不要**重启 `.45` geth。

## 范围外

- 新的 SI 命令或域名
- wipe 任一主机或重启任何 validator
- 宣称 P1 追链已完成
- 把现役 SI `udp_relay` 当 OS UDP
- 把生产混合 P2P（公网 + L0）当默认
