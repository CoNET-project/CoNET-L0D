## 目标

把 overlay IPv4（发往对端 vIP 的 geth / beacon TCP）做成钱包对钱包字节流。优先 **SI 独占占用管道 + 应用层 duplex**：`l0_listen` / `l0_connect`；要约走长期 Chat SSE；接受 / 拒绝 / 帧为占用 L0 管道上的 AES。`duplex_reject` 或无 `duplex_accept` 或无占用管道则保持 **P1 gossip**。SI **不实现** `duplex_*`。不得把 `p2p_stream_*` 或 `listenKind: "l1p2p"` 写成现役。禁止发 `command: "mining"` + `listenKind: "duplex"`。

## 线合同（duplex 优先，P1 gossip 回退）

| 对象 | 加密目标 | HTTP |
| --- | --- | --- |
| `duplex_offer`（overlay AES 钥 + 会话 listen 钱包） | 对端 **长期 user PGP** | 健康入口 **A ≠ B**。普通 Chat gossip 到现有通道 SSE |
| 独占 L0 listen | **本机 B route PGP** | `l0_listen` 或 `mining` + `listenKind: "l0"`，经 **C ≠ B**。不得带 overlay `Securitykey`。crate MVP：按端口通道 EOA |
| `l0_connect` | **目标** mailbox **B route PGP** | 占用空闲 L0 SSE；随后同一 TCP 上 AES blob。已占用 → 409 |
| `duplex_accept` / `duplex_reject` | 占用发起方 L0 管道上的 AES | 不是 user-PGP POST。接收方占用 `W_I` 后的首个 AES blob |
| Overlay IPv4（duplex 数据） | AES 封 `duplex_frame` JSON；`payload` = `L0D1\|\|IPv4` 的 standard base64 | 占用对端 L0 管道。一层 AES。不是 PGP |
| P1 gossip 回退 | 对端 **user PGP**，再 wrap（`NoPush`）给 **B route PGP** | 仍是 `{ "data" }` — 禁止 HTTP 旁路字段 |
| Chat 池 listen（要约） | **B route PGP**，`command: mining` + `listenKind: "chat"`，且必须用 **专用 routing EOA**（可选 `[[l0.channels]]`：8400 / 4200 / 4300 各一个 EOA + SSE） | 健康入口 **C ≠ B** |

HTTP JSON 只能是 `{ "data": "<OpenPGP armor>" }`。禁止在 HTTP 对象上放 `NoPush` / `beamioNoPush`。

信封（内层明文，再 OpenPGP）：

```json
{"type":"conet_l0d_overlay_v1","from":"0x…","seq":1,"ipv4":"<一个 IPv4 数据报，或若干个拼接后的 standard base64>"}
```

`ipv4` 可以是一个完整 IPv4 数据报，也可以是多个拼接；入站按 IPv4 `tot_len` 拆包（非法 `tot_len` / 测试夹具仍当一包）。类型不变；HTTP 仍只 `{ "data" }`。两机 `conet-l0d` 必须同发新二进制——旧对端会把拼接字节当成一个 TUN 包。

Overlay 信封没有 `signMessage`。Listen 只在 SI 外层 wrapper 上做 EIP-191。禁止把明文 JSON 当作 `data` POST。

AddressPGP：[`0x684b0ac760cEE9c9b85de36d69746420648Cf9e2`](https://mainnet.conet.network/address/0x684b0ac760cEE9c9b85de36d69746420648Cf9e2)。RPC：`https://rpc1.conet.network` 或 `https://publicrpc.conet.network`。

## 配置

`[l0]` **默认关闭**。**经授权**的两机实验室可以把主机副本的 `[l0]` **打开**（git 里的 `config/conet-l0d.{45,98}.toml` 仍可保持注释关闭）。这仍不是公开 mailbox 产品。经授权实验室已在两机 TUN 写入双向 IPv4，完成 overlay geth **与** beacon TCP，并正在经 overlay 做 CL initial-sync。追链 **进行中**（EL 仍为 `0x0`）。

```toml
[l0]
enabled = false
rpc = "https://rpc1.conet.network"
address_pgp = "0x684b0ac760cEE9c9b85de36d69746420648Cf9e2"
# entries = ["https://<existing-guardian>.conet.network"]
# listen_entries = ["https://<existing-guardian>.conet.network"]
# routing_eoa = "0x<dedicated-routing-eoa>"
# routing_key_file = "/etc/conet-l0d/routing.key"
# routing_eth_key_file = "/etc/conet-l0d/routing.eth"
# mailbox_route_pgp_file = "/etc/conet-l0d/self-mailbox-route.asc"

# [[peers]] 实验室覆盖（不得打日志）：
# user_pgp_file = "/etc/conet-l0d/peer-user.asc"
# route_pgp_file = "/etc/conet-l0d/peer-route.asc"
```

Routing EOA ≠ Chat 钱包 ≠ deposit keystore ≠ fee recipient。不得把密钥文件打进日志。

出站 **fail-closed**：需要 `[l0].enabled`，以及对端 **user PGP** 文件、对端 **route PGP** 文件、至少一个 entry。禁止只加密给 user PGP 就 POST。`routing_key_file` 是入站解密用的 OpenPGP **私钥**证书，出站不需要。`routing_eth_key_file` 是 EIP-191 listen 用的 hex secp256k1 钥（**不是** OpenPGP）。Listen HTTP+SSE **fail-closed**：enabled 加上 `listen_entries`（C ≠ B；禁止回退出站 `entries`）、`mailbox_route_pgp_file`（本机 B route **公钥**）、`routing_eoa`、`routing_key_file`，以及 recovered 地址等于 `routing_eoa` 的 `routing_eth_key_file`。Listen 为 EIP-191 + SI `{ message, signMessage }` base64。**未**打开生产 SI listen。测试只用 wiremock。禁止在 B 可解密的 listen 命令里放 `Securitykey`。

可选 `[[l0.channels]]`：**每个 overlay 端口**（`8400` geth TCP、`4200` beacon TCP、`4300` discv5 UDP）一套 routing EOA + OpenPGP 私钥 + EIP-191 钥 + mailbox route 公钥 + listen SSE。出站按知名 **源或目的** 端口分类（回程 SYN-ACK 的目的端口是临时口）。加密给对端 **该端口的 user PGP**；同一 VIP 的第二条 `[[peers]]` 不得 skip。未配 `[[l0.channels]]` 时仍是一个 EOA 吃全部端口。`:4300` 仍是 overlay IPv4，**不是** SI `udp_relay`。禁止两条 SSE 绑同一 `routing_eoa`。

## 本阶段评估（2026-08-18 overlay 合批 + POST 并发）

每包一次 OpenPGP + HTTP 会把 overlay 帧丢出队列（两机都出现 queue-full），CL initial-sync 远落后 tip。crate 现按 dest 把 IPv4 合进同一信封，并把 POST worker 提到并发 **32** / 队列 **2048**。

已授权：先拷两边新二进制，再**同时只重启** `.45` / `.98` 的 `conet-l0d`（约 00:37Z）。**不要**重启 geth/beacon。

| 断言 | 结论 |
| --- | --- |
| 两机都跑合批二进制 | **通过**（7.4 MiB @ 00:37Z；按 dest 合批 flush，大量 16 包 / 12 KiB） |
| 重启后 POST / inbound queue-full | **通过**（00:37:40 之后两机 0 丢帧；更早日志是升级前的） |
| 只重启 l0d 后 overlay TCP | **通过**（`.45` `100.64.0.5:43264` → `:8400`，`:51152` → `:4200`；geth `0x1`；beacon `connected=1`） |
| CL initial-sync 速率 | **加快，未完成**（00:41Z `head_slot` `769791` / `sync_distance` `169755`；重启后 90s 约 +256 slot） |
| 追链 | **未完成**（EL 仍为 `0x0`） |

## 本阶段评估（2026-08-18 00:44Z 追链受 Prysm 限速）

合批二进制之后，**限速不在 overlay**：00:37:40 之后 queue-full 为 0，overlay TCP 仍 ESTAB，geth `0x1`，beacon `connected=1`。`.45` 上 Prysm `initial-sync` 以 **3.2 块/秒** 处理（`batchSize=64`；只重启 l0d 时短暂到过 6.4），自估 **约 15 小时**。不要再靠加大 crate 合批或发明 SI 流来「加速」。本追链门仍开。**单独**的实验室 UDP/DHT 通讯实验可以跑（[P2.zh-CN.md](./P2.zh-CN.md)）；它不关闭本门，也不等于 P2 产品完成。**2026-08-18 约 17:28Z：** 授权 `.45` `restart-beacon`（不动 geth）清掉拨号 backoff 后，overlay discv5/libp2p TCP 恢复；CL 又回到 `Processing blocks`。EL 仍为 `0x0` 是 CL 滞后，不是 overlay 又断。

授权 L0_ONLY `.45` 上，追链 **只有**同时满足下表才算通过：

| 门 | 通过 |
| --- | --- |
| Overlay TCP | 对端 vIP `:8400` 与 `:4200` 均为 ESTAB |
| 对等 | geth `net_peerCount ≥ 1`，beacon `connected ≥ 1` |
| CL | `is_syncing=false` 且 `sync_distance ≤ 64` |
| EL | `eth_blockNumber` 离开 `0x0` |
| Overlay 队列 | 上次 `conet-l0d` 启动后无持续 `queue full` |

只读抽检（不重启 EL/CL/l0d）：

## 范围外（不算 crate bug）

- 新 SI 命令或新域名
- 在生产 proposer 或未授权主机上通告 overlay vIP
- 重启或 wipe `.98` / 任何 validator
- 生产 discv4 / discv5（实验室 UDP 通讯见 [P2.zh-CN.md](./P2.zh-CN.md)；DNAT 后 `.45` `ss` 可能显示枢纽公网 `:4200`（原目的，不是漏公网）；不是已关闭的 P2 产品）
